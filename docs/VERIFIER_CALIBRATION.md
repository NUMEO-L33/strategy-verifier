# 검증기 캘리브레이션 & 이음새 감사

Date: 2026-09-29

연구 전용. 자문 아님. 주문 경로 없음.

## 목적 — 검증기 자신을 검증한다

검증기가 "이 전략은 우위가 없다(NOT_CONFIRMED)"고 말할 때, 그 판정을
믿으려면 **계기 자체가 정확한지**를 먼저 증명해야 한다. 저울로 무게를
재려면 아는 추(1kg, 0kg)를 올려 눈금이 맞는지 확인하는 것과 같다.
여기서는 답을 아는 합성 시장 두 개를 **실제 변환·측정 경로**
(`convert-binance-um-klines --bar-path ohlc` → graph_v1 `verify-run`)에
그대로 태워 계기의 눈금을 확인한다.

## 방법 — 양성/음성 대조

동일한 최소 graph_v1 프로브 정의(모든 봉이 롱, 진입 간격 40봉, 성공
밴드 ±5%/지평 120이벤트=30봉)를 두 데이터에 적용한다.

- 음성 대조: 무편향 기하 랜덤워크(드리프트 0). 대칭 ±5% 밴드에서
  favorable 비율은 코인(≈50%) 이어야 하고 Wilson 구간이 0.5를 포함해야
  한다.
- 양성 대조: 같은 과정에 강한 상승 드리프트를 심는다. favorable 비율은
  50%를 크게 웃돌고 Wilson 구간이 통째로 0.5 위여야 한다.

계기가 상수(예: 항상 50%)를 뱉으면 음성은 통과해도 양성이 실패한다.
노이즈에서 우위를 만들어내면 음성이 실패한다. **둘 다 통과 = 계기가
진짜 우위와 노이즈를 구별한다**는 증명.

## 결과

음성 대조(프로브, 5개 시드): favorable 비율 44.8 / 51.0 / 52.4 / 52.7 /
54.7% — 전부 코인 근처, Wilson 구간 모두 0.5 포함.

양성 대조(프로브, 상승 드리프트): favorable 138/150 = **92.0%**,
Wilson 95% [86.5%, 95.4%] — 통째로 0.5 위. 음성과의 격차 ≈ 41%p.

SMC 풀링 정의 자체를 노이즈에 태움(3개 시드, 변동 볼륨): 성립 127~146건,
favorable 비율 43.7 / 50.4 / 53.8% — 전부 코인 근처, 구간 모두 0.5 포함.
즉 **그 "no"를 뱉은 바로 그 정의가 노이즈에서는 우위를 만들지 않는다.**

## 결론

계기는 진짜 우위(92%)와 노이즈(≈50%)를 넓은 격차로 구별한다. 따라서
실데이터에서 나온 SMC의 favorable 53.55%는 파이프라인 결함이 아니라
**믿을 수 있는 측정**이며, "우위 없음" 판정은 근거 있는 결론이다. 이
결과는 `tests/test_verifier_calibration.py`로 고정되어, 엔진이 훗날
망가지면 회귀 테스트가 즉시 실패한다.

## 이음새 감사 — 세션 격리 1건 수정, 무결성 게이트 1건 정정

### 1. 세션 격리 — 실제 결함, 수정함

`--input-session-mode {single,prefix,file}`를 받아도 그래프 엔진
(`run_graph`)은 이 값을 쓰지 않았다. 모든 입력이 하나의 연속 엔진으로
들어가 바가 절대 시각(`ts_ms // bar_ms`)으로만 나뉘었다. 그래서 여러
시장을 한 번에 넣으면 한 시장 꼬리의 결과 지평과 지표 워밍업이 다음
시장 머리로 샜다.

수정: `run_graph_grouped`(src/strategy_verifier/verifier/graph.py)가
입력을 `capture_session_group_id`로 세션 그룹(single→1, file→파일별,
prefix→접두사별)으로 나누고, **그룹마다 새 엔진**으로 돌린 뒤 결과를 셀
단위로 합산한다. 그룹이 하나면 기존 단일 엔진 경로를 그대로 써서 바이트
동일(하위 호환). CLI와 UI 모두 `run_verifier_definition`을 거쳐 이 경로를
쓴다.

검증: prefix 풀링 결과 == 시장별 단독 실행의 셀 단위 합. 경계 오염을
보장하도록 만든 데이터에서 예전 연속 경로는 favorable 1건을 누출하고
격리 경로는 누출하지 않는다.

### 2. 무결성 게이트 — 결함이 아니었음 (감사 정정)

처음 감사에서는 `--integrity-gated`가 `verify-run`에서 무효라고
판단했다. 이는 **틀렸다.** 감사가 `verify-run` 처리 블록만 읽고,
CLI가 `verify-run`/`verify-read` 입력에 공통으로 적용하던 전처리 단계
(`prepare_capture_inputs` — 중복·역순 행 제거, `--require-integrity-safe`
시 fail-closed, 무결성 manifest 출력)를 놓쳤다. 라이브러리 함수
`run_verifier_definition`이 직접 게이트하지 않는 것은 설계상 맞다 —
게이트는 입력 준비 단계의 책임이다.

정리: 그 오진 때문에 덧붙였던 이중 게이트는 이 저장소에서 제거했고,
공통 전처리 한 곳만 남겼다. 테스트가 그 동작을 고정한다 — 더러운
캡처(중복+역순)에 `--require-integrity-safe`는 exit 1, `--integrity-gated`
는 성공하며 게이트된 측정이 깨끗한 원본 측정과 바 단위로 일치하고,
리포트 머리에 `integrity_mode: raw|gated` manifest가 찍힌다.

### 영향

SMC 판정에는 두 건 모두 영향이 없었다. 변환된 klines는 이미 정렬·정제
상태(malformed=0, out_of_order=0)였고, 다시장 측정은 시장별로 따로
실행해 합산했다. 수정 후 다시 돌려도 결과는 같다.
